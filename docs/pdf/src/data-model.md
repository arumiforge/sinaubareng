## Tujuan

Ini adalah model relasional SIGRAK di MySQL 8 (D-007), direvisi dari catatan pengembang aplikasi lama agar sesuai dengan konsep baru: siswa berupa catatan data, konten berasal dari templat, dan guru memiliki beberapa kunci AI. Dokumen ini menetapkan batas entitas, key, invarian, dan kepemilikan. Dokumen ini **bukan** spesifikasi migrasi: setiap tabel mendapat tinjauan skema sendiri saat migrasinya ditulis.

## Konvensi

| Topik | Aturan |
|---|---|
| Nama | Bahasa Inggris, tabel snake_case jamak, model StudlyCase tunggal (konvensi repo) |
| Key | Primary key `bigint` auto-increment untuk join internal. Baris yang tampil di URL atau props (dokumen, generation, undangan, murid, keanggotaan sekolah, tahun ajaran, kelas, slot jadwal; D-182, D-241) juga mendapat `public_id` UUIDv7 (Laravel `HasUuids`), agar jumlah data tidak bocor dan id tidak bisa ditebak berurutan |
| Foreign key | Selalu dideklarasikan, selalu diindeks, dengan pilihan `ON DELETE` yang eksplisit |
| Nullability | `NOT NULL` secara bawaan. `NULL` hanya bila ketiadaan punya arti tersendiri, yang disebutkan di dokumen ini |
| Himpunan tetap | `varchar` + `CHECK (col IN (…))` (MySQL ≥ 8.0.16 menegakkan CHECK), dicerminkan oleh PHP backed enum |
| Waktu | `timestamp` dalam WIB (`Asia/Jakarta`, D-165): aplikasi dan sesi MySQL-nya sama-sama memakai `+07:00`. Tanggal tanpa jam memakai `date` |
| Uang | Rupiah bilangan bulat (`bigint`), tanpa float |
| Penghapusan | Tanpa soft delete. Hapus permanen setelah konfirmasi yang menyebut nama itemnya. Siklus hidup dimodelkan sebagai `status` eksplisit bila baris tetap terlihat tetapi tidak aktif |
| JSON | Hanya untuk konten yang bentuknya ditetapkan JSON Schema templat (`documents.content`, `generations.specification`, keluaran langkah) dan untuk data rujukan yang diimpor. Tidak pernah menjadi tempat kolom yang perlu di-query |
| Tahun yang ditutup | Tahun ajaran yang ditutup hanya-baca: bisa dilihat dan diunduh, tidak pernah diubah (D-318) |
| Pengaturan dan log | Pengaturan sekolah ada di satu catatan per sekolah (isiannya disebut di bagian-bagian berikut). Setiap perubahan pengaturan konsol (model AI, masa simpan, cakupan staf, reset 2FA) dicatat |

## Tenancy dan akses

- Setiap tabel milik sekolah punya `school_id NOT NULL`, diindeks, dan indeks gabungan diawali kolom itu.
- MySQL tidak punya row-level security, jadi batasnya ditegakkan di aplikasi dengan cara **fail-closed**:
  - Trait `BelongsToSchool` secara bawaan menambahkan global scope dari keanggotaan yang sedang aktif. Melewatinya harus eksplisit (`withoutSchoolScope()`) dan hanya boleh di konsol internal serta di job yang menyebut sekolahnya.
  - Setiap aksi controller diotorisasi lewat policy.
  - Feature test memastikan pengguna sekolah A tidak pernah bisa membaca baris sekolah B (satu tes IDOR/BOLA per resource).
- Pengawas membaca data lintas sekolah binaannya lewat `supervisor_assignments` dengan policy hanya-baca. Mereka **tidak melihat baris tingkat siswa**.
- Data siswa (catatan, absensi, catatan guru, nilai) hanya bisa dibaca guru kelas itu, operator, dan kepala sekolah (aturan dari catatan pengembang). Catatan konseling (BK) hanya terlihat oleh penulisnya, wali kelas, dan kepala sekolah.
- Data kesehatan (D-215) dan hasil asesmen yang sensitif (sosial-emosional, kebutuhan khusus, minat atau bakat, D-350) hanya terlihat oleh guru kelas itu, GPK yang ditugaskan, operator, dan kepala sekolah; tidak pernah dikirim ke AI dan tidak pernah disimpan sebagai label permanen. Pengawas hanya melihat total kelas atau sekolah.
- Support Tim SIGRAK boleh membuka tampilan sekolah secara hanya-baca berdasarkan MoU sekolah, dengan data agama dan kesehatan disembunyikan; satu baris internal disimpan per sesi support (D-341).

### Profil kebijakan dan rule set (D-354…D-356)

**Dibangun di P5-03k dan P5-03l (D-355, D-356, D-378).** Sebuah **resolver profil kebijakan** mengembalikan `PolicyProfile` untuk (tahun ajaran, jenjang, wilayah): untuk setiap domain, versi aktif yang rentang tahun ajarannya mencakup tahun itu. Resolver ini menggantikan penunjuk `allocation_versions` di `config/curriculum.php`; perilaku D-230 tidak berubah. **Profil Jenjang** adalah catatan data kecil berversi per jenjang (`sd`, `mi`, D-356): kementerian, kode rule set per domain, kerangka karakter yang aktif (MI menambah KBC; isian KBC untuk SD mati secara bawaan, admin bisa menyalakannya, D-368), isian tambahan RPM, tujuan ekspor rapor (e-Rapor SD atau RDM), bawaan JTM wali kelas (D-212), dan asesmen eksternal. **Sinkronisasi offline (Di Kelas, D-016).**

- Perangkat membuat baris dengan `client_uuid` dan mengantrekannya di IndexedDB. Endpoint sinkronisasi melakukan upsert berdasarkan `client_uuid`, sehingga pengiriman berulang tidak pernah menggandakan data.
- Bila terjadi konflik, penulisan terakhir yang menang per baris, dan waktu perangkat disimpan di `recorded_at_device` di samping timestamp server.
- Yang juga bekerja offline selain kehadiran, jurnal, dan catatan murid: pertemuan RPM hari ini dan besok (cache hanya-baca, tanpa baris), antrean pindai Pindai LJK (`sheet_scans`), serta pengisian observasi dan rubrik (D-289, D-349). Antrean disinkronkan sebelum muat ulang "Versi baru tersedia" (D-321).
